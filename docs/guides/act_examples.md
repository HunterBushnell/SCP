# ACT-Sourced Native Examples

These five families are **staged and smoke-tested**, not completed SCP
walkthroughs or independently biologically validated releases. The existing
PV example remains the public notebook default while their characterization,
manual tuning, and demonstration datasets are developed separately.

## Catalog and tune meanings

| Family | Loader | `orig` | `tuned` | `reference` |
|---|---|---|---|---|
| [ACT_Spiker](../../cells/ACT_Spiker/README.md) | HOC `Spiker` | ACT starting model | Identical, initially untuned working copy | Known target model |
| [ACT_BursterCa](../../cells/ACT_BursterCa/README.md) | HOC `BursterCa` | ACT starting model | Identical, initially untuned working copy | Known target model |
| [ACT_LAA](../../cells/ACT_LAA/README.md) | HOC `Cell_A` | ACT starting model | Identical, initially untuned working copy | Known target model |
| [ACT_L5](../../cells/ACT_L5/README.md) | Allen manifest | Original Allen bundle | Imported ACT tuned variant | Not staged |
| [ACT_SST](../../cells/ACT_SST/README.md) | Allen manifest | Original Allen bundle | Imported ACT tuned variant | Not staged |

Sources are pinned to ACT commit
`2b3fdc190107b8242e3496329cfdf240abd09694`. HOC `orig` uses
`data/<family>/orig/template.hoc`; `reference` uses its
`target_template.hoc`. A known target is not an exported optimization result.
The ACT notebooks apply learned HOC parameters in memory; this staging pass
does not reconstruct or invent an optimized HOC model. `template_known_passive`
and segmented HOC variants are not imported.

Allen `orig` uses ACT's `adb` directory, whereas `tuned` uses `seg_tuned`.
ACT's directory named `orig` is an altered starting variant, not the pristine
Allen download, and is not staged here. The selected fit is exactly the one
referenced by each manifest: alternate `FINAL` checkpoint files are not
silently substituted. This matters for SST, whose manifest-selected fit and
`FINAL` checkpoint differ. Each variant keeps its matching MOD sources;
segmentation can change equations, so exchanging fit files between libraries
does not reproduce the same model.

| LAA | 31°C | −70 mV |
| L5 | 34°C | −90 mV |

These explicit initial settings follow native fit/HOC or documented ACT
workflow settings. They do not claim to reproduce every historical ACT
optimization experiment. SCP reapplies them after construction and before
each protocol. L5 explicitly selects all-active utilities with stub axon;
SST uses standard Allen utilities. SST retains its inherited multi-root
morphology warning; the source morphology is not edited to suppress it.

## Start using an example

The models and mechanisms are already staged; there is no need to download
Allen data, install ACT, or execute an ACT/network builder. Select a family and
tune in the compact notebook. In detailed notebooks, set `cell_name` to the
ACT-prefixed family and `tune_name` to the desired tune, with
`project_name = None`. If rerunning Step 1, set `MODEL_SOURCE_OVERRIDES = None`
to use the stored recipe rather than the notebook's explicit PV download
example. Retain the existing configs instead of overwriting them.

For example, from the SCP root:

```bash
python scripts/check_setup.py --cell ACT_Spiker --tune orig --steps 1 2 3 5 --compile-modfiles
python run_pipeline.py --cell ACT_Spiker --tune orig --iclamp
```

New configs select cell-only IClamp routing, but timing/current fields remain
generic SCP placeholders, **not validated stimulation protocols**. Review
and set them before scientific use. Targets use `target_source.mode: "none"`;
no target traces, manual values, citations, synapse configs, or scientific
datasets are generated by staging. Core Steps 2/3 can characterize without
targets. Reference-cell measurements and target setup are later manual work.

The configured HOC native file and section map are explicit. The native
templates, geometry, segmentation, and mechanism parameters are unchanged.
Only Spiker's one, BursterCa's eight, and LAA's ten intrinsic MOD sources are
needed; unrelated GUI/synaptic/driver files are not included. Allen bundles
contain their selected fit, morphology/marker, and complete 16-MOD library.

### Process boundaries and manual edits

**Restart the kernel or use a fresh process when switching tunes or families.**
Different copied files can declare the same HOC template or mechanisms;
separate folders do not isolate NEURON definitions. The compact configured
simulation path already uses fresh processes. Never run independent NEURON
models concurrently in threads of one Python process.

Manual native-file edits persist in that tune. HOC `tuned` is the intended
editable working copy; do not overwrite `orig` or `reference` accidentally.
Allen `tuned` already contains an imported ACT variant, so an explicit
orig-to-tuned overwrite would discard it. Initial provenance identifies the
imported bytes; after manual edits, retain that lineage and refresh derivative
documentation/provenance rather than claiming the files remain exact copies.

## Staging checks and future work

Checks compile/load each tune in a fresh subprocess, exercise short passive,
active/FI and Step 5 IClamp protocols with temporary overrides, validate finite
matching recordings and runtime conditions, and exercise a BMTool facade test
without BMTool, current-model inspection, and temporary saved-result loading.
No acceptance assertion is made about spiking, rheobase, passive properties,
or biological correctness. Staging outputs are not committed as datasets.

Later work will develop protocols/targets, manually characterize and tune
working copies, configure synapses only where justified, and curate saved
results with analysis/restoration demonstrations. Only then should these
replace the existing PV-centered public workflow.

Each tune has `SOURCE_PROVENANCE.json`; each family retains `LICENSE.ACT`.
Original source credits remain in place. Some Allen SWC comment headers contain
historical `C:/Users/...` source paths inherited from upstream. These are inert
metadata, not SCP runtime paths; they are retained to preserve native bytes and
provenance rather than edited during notebook cleanup. See
[Third-party notices](../../THIRD_PARTY_NOTICES.md),
[Model loaders](../reference/model_loaders.md), and
[Project workspaces](project_workspaces.md). Earlier LUT examples now live in
local research workspaces, not this public catalog. Git history is unchanged.
